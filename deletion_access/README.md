# SubgraphX attack access: deletion-only versus mixed edits

## Registered comparison

The attacker corrupts stored graph topology while node features and classifier parameters remain fixed. Compare (a) deletion-only access to existing non-self-loop transaction rows and (b) the existing mixed domain allowing deletions plus additions at absent ordered pairs. Edits stay within the original clean incoming two-hop candidate node set. Parallel rows remain individually removable; self-loop edits and parallel additions are disallowed. This is not a claim of economically valid transaction manipulation, temporal feasibility, feature-consistent changes, a restricted-knowledge black-box attack, or a defense.

Every candidate makes exactly six distinct directed edits. Both access conditions use the same frozen models, target cohort, trial seed 2026, SubgraphX settings (two hops, six children, five rollouts, five Shapley samples, terminal size three), native selected sets, and preservation-first/cosine-distance-second ranking. Both conditions are freshly searched, rather than filtering previously successful attacks.

Within each condition compare 40 adaptive proposals (one-edit incumbent substitutions, an independent restart every tenth proposal) with 40 independent random proposals and their first random proposal as a one-draw baseline. Save every candidate and both trajectories, including prediction-changing outcomes. Cache repeated candidates without changing proposal count; report unique evaluations and elapsed time separately. Exact-budget cases with only six removable rows are eligible; repeated proposals then honestly reflect the restricted search space. No early stopping based on attack effectiveness.

Full cohort: 30 randomly selected targets per dataset, AMLSim and HI-Small, drawn from the previously registered correctly detected illicit test targets after requiring at least six removable rows. Selection seed 271828; sampling uses only candidate feasibility, never attack outcomes. The eligibility census and sampled IDs are saved before new attack evaluation. One search/explanation trial per target is intentional for the two-day time budget; no between-trial SD or generalization over training seeds is claimed. The full test set has been used previously; this is an exploratory follow-up, not untouched confirmation data.

Validation: one separate registered validation target per dataset with six removable rows. Run the same complete two-condition comparison before full execution. Require unchanged model weights, original/full/cached/local prediction parity, repeatable same-seed SubgraphX sets, exact budgets and permissions, valid row IDs, finite metrics, and appropriate bounds. Technical failures halt promotion. Attack success is never a gate. All final selected graphs receive an independent full-graph predictor check. The full phase enumerates all 60 frozen test targets and reuses cases only with identical provenance.

## Outcomes and interpretation

Primary: native-set cosine similarity, reported jointly with label preservation. Also report Jaccard, absolute original-class probability change, clean/attacked selected-set sizes and empty flags, additions/deletions, and hard/soft necessity and sufficiency failure. Native SubgraphX sets are never truncated to top-k. Record explanation edges directly removed by the attacker and overlap after restricting both native sets to surviving graph edges, to expose mechanical loss of explanatory edges; this restricted overlap is supplementary and cardinality-dependent.

Main paired effect: deletion-only minus mixed similarity within target and search method. Positive values indicate weaker disruption under deletion-only access. Also report differences in label-change rate and probability change, and similarity among targets where both conditions preserve labels. Complete-case selection is based on technical coverage, never attack success. All-target tables remain primary. Target-bootstrap 95% intervals are descriptive and conditional on these graphs and fixed models; dependence between graph nodes and training randomness is not modeled. Hypothesis direction is not a success criterion.

One isolated controller and DGL worker use separate files and logs under this folder. The controller uses one CPU thread; the unchanged DGL worker uses two. Existing source files and ongoing HI-Small results are read-only inputs. No PGExplainer or GNNExplainer transfer computation is included, keeping the experiment focused on access restrictions.

Run the recorded main interpreter with `deletion_access/run.py pipeline`. Pilot/full reports, manifests, status, candidate evidence and summaries are saved under `deletion_access/results/`. The background process is launched hidden at lower priority. Reports are explicitly provisional until their frozen cohorts are complete.
